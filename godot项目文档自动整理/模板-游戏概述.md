# 模板：游戏概述

用途：`1项目文档/0-设计/游戏概述.md`，项目的第一页，用来对齐"到底在做什么"。

```markdown
# 游戏概述

> 最后更新：YYYY-MM-DD | 状态：草案 / 生效

## 一句话卖点

（一句话说清玩家为什么玩这个游戏。）

## 基本信息

- 游戏类型：
- 目标平台：
- 目标受众：
- 单局时长：
- 参考作品：（参考了哪些游戏的哪些部分，不抄什么）

## 玩家体验目标

玩家在游戏中应该持续感受到什么情绪/体验（如：紧张、解压、收集欲、成就感）。

## 核心差异点

与同类游戏相比，本作刻意做强的 1-3 个点。

## 范围边界

- 本次版本做：
- 本次版本不做：（明确划出去的内容，防止范围蔓延）

## 未决问题

- [ ] <待定项，附日期>
```

## 维护要点

- 「一句话卖点」是整个文档的北极星，其他地方的表述都要能追溯到它。
- 「范围边界」比「做什么」更重要，改动超出边界时触发冲突处置流程。
- 项目方向调整时，这篇要第一个改，否则下游文档全部失真。
