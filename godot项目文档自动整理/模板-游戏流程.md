# 模板：游戏流程

用途：`1项目文档/1-架构/游戏流程.md`，从玩家视角描述流程与状态流转。

```markdown
# 游戏流程

> 最后更新：YYYY-MM-DD | 状态：生效

## 玩家视角流程

标题 → 主菜单 → 关卡选择 → 关卡内 → 结算 → 返回关卡选择

## 状态流转

| 状态 | 进入条件 | 退出条件 | 期间玩家可做什么 |
|---|---|---|---|
| 主菜单 | 启动游戏 | 开始游戏 | 选择关卡、调整设置 |
| 关卡内 | 选中关卡并确认 | 达成目标或失败 | 移动、战斗、使用道具 |
| 暂停 | 玩家主动暂停 | 恢复游戏 | 查看信息、调整设置 |
| 结算 | 关卡结束 | 确认结果 | 查看奖励 |

## 状态持有原则

- 谁决定"当前处于什么状态"
- 状态切换时，正在进行的玩法如何处理（强制中断 / 等待结算）

## 异常处理

- 关卡加载失败：返回关卡选择并提示
- 中途退出：记录当前进度，下次可从该关卡继续
- 状态切换被打断时如何回滚

## 未决问题

- [ ] <待定项，附日期>
```

## 维护要点

- 「进入 / 退出条件」必须成对写全，缺一边就会出现流程断裂。
- 每个状态都要有可达路径：新增状态后，检查是否存在无法进入或无法退出的状态——这是 L3 冲突的判定项之一。
- 状态名用玩家/策划能懂的词，不用实现内部的状态枚举名。
