# 模板：核心玩法

用途：`1项目文档/0-设计/核心玩法.md`，玩法的骨架，冲突判定最主要的比对基准。

```markdown
# 核心玩法

> 最后更新：YYYY-MM-DD | 状态：草案 / 生效

## 核心循环

玩家在一次循环中重复做什么。（用"玩家 → 行为 → 反馈 → 结果"的句式描述。）

例：探索地图 → 遭遇敌人 → 战斗取胜 → 获得资源 → 强化角色 → 挑战更强敌人

## 玩家行为集

| 行为 | 触发方式 | 结果 | 限制条件 |
|---|---|---|---|
| 移动 | 方向键 | 角色位移 | 战斗中不可移动 |
| 攻击 | 按键 | 对目标造成伤害 | 有冷却 |

## 规则

- 规则一
- 规则二

## 胜负条件

- 胜利：
- 失败：

## 节奏曲线

- 前期（引导期）：教什么、多长
- 中期（成长期）：难度如何爬升、什么节点给新机制
- 后期（挑战期）：难度天花板、终局目标

## 难度设计

- 难度维度有哪些（敌人强度 / 时间压力 / 资源稀缺度）
- 玩家可用的调节手段

## 边界情况

- 多个效果同时触发时的优先级
- 极端操作下的处理（如同时按下冲突按键）

## 未决问题

- [ ] <待定项，附日期>
```

## 维护要点

- 任何玩法规则改动都要先与本篇比对，矛盾即触发冲突处置流程。
- 「规则」只写玩家能感知的规则，不写实现判断逻辑。
- 「边界情况」最容易缺失，但恰恰是后期 bug 和体验争议的高发区，必须写。
