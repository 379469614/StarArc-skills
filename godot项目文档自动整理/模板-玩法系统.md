# 模板：玩法系统（2-系统/ 通用）

用途：`1项目文档/2-系统/<系统名>.md`，一个玩法系统一篇。这是使用频率最高的模板。

```markdown
# <系统名>

> 最后更新：YYYY-MM-DD | 状态：草案 / 生效 / 已废弃

## 职责

负责什么。（一句话）

## 不负责

明确不负责什么，避免与相邻系统职责重叠。

## 玩法规则

- 规则一
- 规则二
- 边界情况：<如多个效果同时触发时的优先级>

## 玩家可感知的行为

玩家做了什么 → 系统给出什么反馈 → 结果如何呈现。

## 与其他系统的关系

| 对象 | 方向 | 说明 |
|---|---|---|
| 战斗系统 | 本系统 → 战斗系统 | 道具使用后触发伤害结算 |
| 界面 | 本系统 → 界面 | 数量变化时刷新显示 |

> 详细交互时机登记在 [系统交互](../1-架构/系统交互.md)，本篇只记本系统相关的部分。

## 关键设计取舍

为什么这样设计、放弃了什么方案、代价是什么。

## 数值要点

影响本系统的关键数值维度与调参方向。**具体数值表一律放 [数值框架](../0-设计/数值框架.md)，本篇不重复。**

## 未决问题

- [ ] <矛盾或待定项，附日期>
```

## 维护要点

- 「不负责」区块不能空着，它是防止功能漂移最有效的一栏。
- 数值只写维度和方向，绝不复制具体数值表过来（会立刻失同步）。
- 交互只在 `系统交互.md` 全量登记，本篇写摘要并链回去，避免两处不同步。
- 系统被删除或合并时，整篇标注"已废弃（原因 + 替代方案 + 日期）"，不直接删除。
