# 模板：变更日志

用途：`1项目文档/5-变更日志/YYYY-MM.md`，按月份归档，所有级别的改动都要留痕。

```markdown
# 2026-09 变更日志

## YYYY-MM-DD

- **L1** 玩家初始生命值 100 → 120
- **L2** 新增生命值系统，战斗系统接入伤害与死亡流程 → 更新 [战斗系统](../2-系统/战斗系统.md)、[系统交互](../1-架构/系统交互.md)
- **L3** 移除全局音频管理服务，改为场景内音频 → ADR-0003
- **设计冲突（待决）** 新道具规则与核心玩法中"不可携带消耗品"的描述矛盾，已挂入 [核心玩法 未决问题](../0-设计/核心玩法.md)
```

## 格式规范

每行固定结构：

```
- **<级别>** <改动内容> → <影响的文档链接，可选>
```

- **L1**：只写改动内容，不链文档（设计文档未变）。
- **L2 / L3**：必须列出被更新的文档链接。
- **设计冲突**：单独一行标注"待决"，并指向挂靠的「未决问题」区块。

## 维护要点

- L1 改动也一定要记——它是日后回溯"数值为什么变成这样"的唯一线索。
- 日期按天倒序（最新在最上），同一天内的条目按 L3 → L2 → L1 排列。
- 每月首次写入时创建新文件，并在 `README.md` 索引中更新"本月变更"链接。
- 日志只追加，从不修改历史条目；发现记错了就补一条新条目更正。
