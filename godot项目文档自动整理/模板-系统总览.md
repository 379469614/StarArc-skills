# 模板：系统总览

用途：`1项目文档/1-架构/系统总览.md`，描述"有哪些系统、各自负责什么"，**不描述代码怎么组织**。

```markdown
# 系统总览

> 最后更新：YYYY-MM-DD | 状态：生效

## 系统清单

| 系统 | 职责 | 状态 |
|---|---|---|
| 流程管理 | 掌控整体流程与状态切换 | 生效 |
| 生命值系统 | 管理角色生存状态 | 生效 |
| 背包系统 | 管理道具持有与使用 | 草案 |

## 职责边界

- 流程管理：决定"现在处于什么阶段"，不关心阶段内的具体规则
- 关卡系统：决定"关卡内发生什么"，不决定关卡之间的切换

## 依赖方向

流程管理 ← 关卡系统 ← 战斗系统 ← 生命值系统

（箭头指向依赖方；禁止反向依赖与循环依赖）

## 全局服务

| 服务 | 职责 | 生命周期 |
|---|---|---|
| 流程管理 | 掌控游戏流程 | 全程存在 |
| 存档管理 | 跨会话保留进度 | 全程存在 |

## 变更记录

| 日期 | 变更 | 原因 |
|---|---|---|
| YYYY-MM-DD | 新增存档管理 | 需要跨会话保留进度 |

## 未决问题

- [ ] <待定项，附日期>
```

## 维护要点

- 依赖方向图必须保持单向，发现循环依赖即为 L3 冲突，需用户确认后重构。
- 两个系统职责出现重叠或真空 → 触发冲突处置流程。
- 增删全局服务属 L3（影响面覆盖全流程），必须先确认再写。
