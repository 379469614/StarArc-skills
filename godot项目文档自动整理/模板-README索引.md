# 模板：README.md（文档索引）

用途：`1项目文档/README.md`，整个文档库的唯一入口，AI 每次整理文档时**第一个读**它。

```markdown
# <游戏名> 项目文档

> 最后更新：YYYY-MM-DD | 状态：开发中

## 文档导航

| 分类 | 文档 | 说明 |
|---|---|---|
| 设计 | [游戏概述](0-设计/游戏概述.md) | 卖点、平台、受众 |
| 设计 | [核心玩法](0-设计/核心玩法.md) | 核心循环与规则 |
| 设计 | [数值框架](0-设计/数值框架.md) | 成长曲线与经济循环 |
| 架构 | [系统总览](1-架构/系统总览.md) | 系统清单与职责边界 |
| 架构 | [系统交互](1-架构/系统交互.md) | 协作与通知约定 |
| 架构 | [游戏流程](1-架构/游戏流程.md) | 流程与状态流转 |
| 系统 | [战斗系统](2-系统/战斗系统.md) | |
| 决策 | [ADR 列表](4-决策记录/README.md) | 设计决策留痕 |
| 日志 | [本月变更](5-变更日志/2026-09.md) | |

## 阅读顺序建议

1. `游戏概述` 了解项目全貌
2. `核心玩法` + `数值框架` 理解玩法骨架
3. `系统总览` 理解各系统如何协作
4. 改动具体系统前，先读 `2-系统/` 对应文档

## 维护约定

- 本索引由 AI 自动维护，新增文档必须登记
- 每篇文档开头的"最后更新"日期必须同步刷新
```

## 维护要点

- 新增任何文档，必须在本表登记，否则后续 AI 检索不到。
- 文档删除或废弃时，不删行，改为标注"已废弃"，保留历史可追溯。
- 表格按分类分组，同分类内按阅读顺序排列。
