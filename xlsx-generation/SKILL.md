# 表格生成

1. 使用本技能同目录的 [表格生成工具.py](表格生成工具.py)，不为每次任务重新编写 Python，不手写或修改 xlsx 内部 XML。
2. 模型负责整理用户提供、已有文件读取或明确要求设计的数据；脚本负责写表，不推测业务数值。
3. 只依赖 Python 3.10+ 和 openpyxl。先运行脚本的 `--依赖检查`；若缺少 openpyxl，立即停止生成，告知用户按输出命令安装，不自动安装，也不改用其他生成方式。
4. 禁止读取或将 `表格生成工具.py` 的完整源码加载到上下文，包括分段读取后拼成全文。正常使用时直接执行脚本，仅通过本技能、`--help`、`--格式` 和运行结果获取必要信息，避免不必要的 token 消耗；确需排错或修改脚本时，仅检索并读取相关的最小代码片段。

## 路径与调用

1. 按 `folder-structure` 目录技能定位 `project.godot`，其所在目录为工程目录，上一级为项目根目录；无法确定时询问用户。
2. 数据表写入项目根目录的 `4数据配置表格/`；文案表写入其中的 `文案表格/`。这两个目录下的 xlsx 均扁平存放。
3. 使用同一个 Python 解释器运行本技能内的脚本，传入 `--项目目录` 和项目根目录绝对路径，通过标准输入传入 UTF-8 JSON。不额外保存 JSON、模板或临时生成脚本；Windows 管道也应设置为 UTF-8。
4. 用 `--help` 查看调用方式，用 `--格式` 获取完整输入示例；参数说明与示例集中在脚本内维护。
5. 默认拒绝覆盖已有文件。任务已经授权替换整个工作簿时才使用 `--覆盖`；它会替换整个文件，输入必须包含所有需要保留的工作表和数据。局部修改时，先读取原表并整理完整输入；若需保留复杂格式、图表或其他脚本不支持的内容，先说明限制，不直接覆盖。

## 输入约定

1. 顶层包含 `文件名`、`分类`、`工作表`。文件名必须是单个 `.xlsx` 文件名；分类为 `数据配置`（默认）或 `文案配置`。
2. `工作表` 为有序列表，每项包含 `名称` 和 `行`；`行` 为二维数组，按 Excel 行列顺序包含表头、类型行及全部数据。一次调用生成一个工作簿，可以包含多张表。
3. 单元格仅接受 JSON 字符串、数字、布尔或 `null`。数组、对象字段按导表格式整理成单元格文本，不直接传 JSON 容器。
4. 空数据用 `null`，脚本会留空；空字符串同样留空。不要为了补默认值填入 `0`、`false`、`[]`、`{}` 或字符串 `null`。用户明确给出的 `0` 和 `false` 正常保留。
5. 字符串始终按文本写入，包括以 `=` 开头的内容、前导零、长数字、日期形文本和 Excel 错误码形文本。需要保留完整数字字符时传字符串；不生成公式或日期类型单元格。

## 填表规则

1. 导出工作表名为 `|` 加纯中文名称，所有数据与文案工作簿中的导出名称唯一；无须导出的说明表不加 `|`。
2. 数据表第 1 行为字段名，第 2 行为类型，第 3 行起为数据；A1 必须为 `ID`，A2 必须为 `key`。其余字段名用中文，可导出字段名及记录 ID 不重复。
3. 配置表使用 `name`、`value`、`type`、`sign`、`description` 五列表头，从第 2 行起填参数；无签名或描述时留空，参数名称不重复。
4. 基本类型使用小写 `int`、`long`、`float`、`string`、`bool`；支持数组 `T[]`、对象 `{类型 字段;类型 字段}` 和引用 `int(表.字段)`、`long(表.字段)`、`string(表.字段)`。数据表中 `none` 或空类型列不导出。
5. 数组单元格使用半角逗号分隔，对象单元格使用半角分号分隔，字段顺序对应类型声明。字符串中的字面逗号和分号按需要用 `\,`、`\;` 转义，`\n` 表示换行；嵌套容器使用配对括号。
6. 保留有效记录的 ID 或配置名称及类型；空数据单元格不等于空记录。不要在有效记录之间插入无意义空行；数据表的注释行以 `#` 开头。

## 游戏展示文本与可读备注

1. 准备生成文本内容时，先确认该内容是否需要在游戏内展示。需要展示给玩家的文本必须调用 `multilingual` 技能：数据表中的对应字段使用文案 key，实际文本按该技能规范写入对应模块的文案表格；已有文案表时更新，没有时使用本技能生成。文案表位于项目根目录的 `4数据配置表格/文案表格/`，不得只生成 key 而遗漏对应文案。
2. 名称转换为文案 key 后，必须在名称字段右侧相邻一列增加“名称备注”等可读名称列，类型行填写 `none`，逐行填写对应的名称，便于直接识别内容。参考 `科技配置.xlsx` 的 `|科技大节点`“名称”字段。文案 key 是该字段保存的值，不应因此把字段类型改为数据表 ID 使用的 `key`。
3. 当 key 或关联编号为纯数字、无法直接理解其含义时，必须增加 `none` 类型的备注列，写明对应名称或含义，优先放在相关字段旁边。参考 `科技配置.xlsx` 的 `|科技等级数值`：“小节点编号”旁的“节点备注”类型为 `none`，用于说明对应的节点名称。
4. `none` 类型的备注列仅用于表格阅读，不导出，不替代正式文案。已有备注列满足要求时复用；名称或对应关系变化时同步更新备注。key 与备注的对应关系必须依据已有配置、文案表或用户说明，无法确定时询问，不猜测。

## 生成与结果处理

1. 脚本保存后自动运行项目根目录的 `4数据配置表格/表格检查工具.py`，传入 `--目录`（完整表格根目录）和 `--json`。它会检查数据与文案两个目录，输出原始检查结果。
2. 按结果中的文件、工作表、单元格和原因，修正本次任务的数据后重新生成并再次调用检查工具；业务意图不明确时先询问，不自行填值。其他既有表的问题仅报告，不擅自修改。
3. 检查仅调用现有检查工具，不额外执行手动读回抽查、Excel 人工检查或导出验证，不另行实现一套表格检查规则。检查工具缺失或无法运行时，停止并报告原因，不宣称检查通过。
4. 退出码 `0` 表示检查通过，`1` 表示检查未通过，`2` 表示依赖、输入、写入或工具运行失败。检查失败时已生成文件仍保留；不要把文件生成成功当作检查成功。
5. 交付时说明生成路径、检查是否通过及提醒内容；如其他既有表导致整体未通过，应如实说明。检查范围以工具返回的说明为准，不宣称已完成真实导出或引用目标验证。
