# GDScript 全中文编程规范

AI 必须严格遵守

## 强制规则
1. **静态类型**：
	- 必须显式类型注解，禁止 `:=`
	- 数组用 `Array[类型]`，字典统一显式标注为 `Dictionary`
	- 类型转换时区分场景：**确定性引用（如通过 `%节点名` 获取固定子节点）直接赋值**（例如 `var 节点: 类型 = %节点名`），利用引擎自动类型检查，尽早暴露配置错误；**仅在动态加载、多态参数等非确定场景**才允许使用 `as`，并必须显式判断转换结果是否为 `null`，严禁一刀切滥用 `as`
2. **中文命名**：
	- 范围：文件名、类名、节点、函数(方法)、变量、常量、枚举、信号等均用中文（uid与引擎自带命名除外），不使用下划线（私有成员除外）
	- 命名规则：中文命名要能清晰表达该内容的具体作用
		- **文件名**：使用名词性短语，功能描述 + 范畴后缀（器/集/池等）；例如 `用户管理`、`日志记录器`、`图像处理工具集`
		- **类名**：使用名词性短语（定语+中心语），或加角色后缀“器/者/接口”；例如 `用户`、`邮件发送器`、`只读配置`、`可序列化`
		- **函数/方法**：动宾/动补结构表达动作，判断用“是否”前缀，回调用“当…时”，内部方法用“_”前缀；例如 `获取用户名称`、`是否为空`、`当数据到达时`、`_更新缓存`
		- **变量**：使用名词或定语+中心语，布尔变量推荐加“是否/已/可”增强可读性；例如 `当前用户`、`事件队列表`、`是否完成`、`可见性`；变量的起名需要注意不要跟全局类名重复了
		- **常量**：使用“常量_”前缀或全大写约定均可，后续命名与变量一致；例如 `常量_应用版本`、`常量_重试次数`
		- **枚举**：类型名用名词短语，成员用形容词/状态（已/未/待）；例如 `颜色.红色`、`订单状态.待支付`
		- **信号**：描述已触发的事件，自然直观即可，不强制加“了/已/被”等字眼；例如 `玩家受到伤害`、`按钮被点击`、`数据变更`、`资源加载完毕`
		- **节点**：使用“所属结构 + 节点”或直接用业务名；例如 `主菜单面板`、`敌人生成点`、`二叉树节点`
		- **例外**：tscn文件的ext_resource与sub_resource ID需要使用 `ASCII 字母、数字、下划线` ，如果在查看tscn文件的时候发现有非这些的ID，则需要顺带修复
3. **前缀规范**：
	- 私有成员、私有方法必须以 `_` 在最前面开头且禁止外部调用
	- 常量必须增加 `常量_` 开头前缀（其他命名禁含“常量”）
4. **类声明**：
	- 当该脚本属于核心数据结构或跨场景复用的基类时，才增加 `class_name`
	- 挂载于单一场景的具体业务脚本，一律不加 `class_name`
	- 全局单例（Project文件中的Autoload）禁止加 `class_name`，如有发现全局单例增加了，则一律处理为去除，并查找是否有需要修复的引用
5. **注释规范**：
	- 注释符号：`@export` 的变量上一行必须要有且只有一行使用 `##` 开头来说明；其他注释均使用 `#` 开头，不限制一定只有一行
	- 变量：**仅当变量名无法完整表达其业务约束、边界条件或非显而易见的用途时，才添加注释**；若变量名已自解释，禁止冗余注释
	- 函数(方法)：上一行必须编写完整中文说明，清晰描述方法的目的、调用约定或重要副作用，而非逐行复述实现代码
6. **通信原则**：当需要与外部脚本进行通讯时，必须严格遵守`向下直接调用，向上发送信号`的解耦原则，绝对禁止任何子节点使用`get_parent()`或`通过路径拼接跨层级`访问上级与兄弟节点
7. **向下调用**：
	- 当需要向下调用内部子节点时，强制使用场景唯一名称（%节点名）（例如 @onready var 节点: 节点类型 = %节点名）
	- 绝对禁止使用相对路径（如 $外层/内层/节点），避免场景层级调整导致脚本大面积崩溃
	- 如果该节点还未设置唯一节点名称，则还应当到对应场景文件中设置唯一节点
8. **代码块顺序**：文件内部必须严格按照以下顺序组织，区块间空两行，区块内变量与变量之间不空行，区块内函数与函数之间只空一行：
	- `@tool`
	- `class_name`
	- `extends`
	- `# 文档说明`
	- `signal`（自定义信号）
	- `enum`（枚举）
	- `const`（常量）
	- `@export`（导出变量）
	- `var`（公有变量）
	- `var`（私有变量）
	- `@onready`（节点获取）
	- 引擎内置虚函数（按照`_init` -> `_enter_tree` -> `_ready` -> `_process` -> `_physics_process` -> `_exit_tree`顺序）
	- 公有方法
	- 私有方法
	- 内部类
9. **代码格式**：Tab 缩进；运算符两侧空格；优先双引号；保留多行数组尾逗号；布尔运算用 `and/or/not`（禁 `&&/||/!`）
10. **警告处理方式**：
	- 绝对禁止在未经明确授权的情况下自动修复任何代码警告
	- 遇到警告（尤其是未使用变量、未使用参数等），严禁使用 `@warning_ignore` 宏，严禁自动删除相关代码，严禁擅自添加 _ 前缀静默警告
	- 代码必须保持原样，仅在输出内容的末尾单独列出当前产生的警告信息，等待后续处理指令
	- 已经手动添加 `@warning_ignore` 的也仅做提示，但不进行主动修改
11. **生命周期原则**：代码内动态实例化的节点对象，必须明确编写 `queue_free()` 的销毁逻辑与触发时机
12. **文件长度控制**：
	- 前置强制拆分规则：
		- 纯计算逻辑、独立数据结构、通用状态机、常量配置集等无节点生命周期依赖的代码，必须拆分为独立 `.gd` 脚本，不得写入节点主脚本
		- 单个脚本仅承载一个核心职责；包含 2 个及以上独立业务逻辑时，必须拆分
		- 纯逻辑拆分的脚本需要不写任何 `extends` ，以确保其是自动继承自 `RefCounted` 
	- 行数约束：
		- 单脚本有效代码（不含空行、纯注释行）严禁超过 800 行，超出必须拆分
		- 500 行为结构检查线：代码编写前若预估单文件超过 500 行，必须先规划拆分方案，再分文件实现
	- 模块引入方式：
		- 仅当前脚本私用的内部模块：在文件顶部常量声明区，使用 const 常量_模块名 = preload("res://路径/模块脚本.gd") 引入
		- 可跨脚本复用的通用类：使用 class_name 全局注册，禁止各处重复 `preload`
		- 两个脚本之间严禁相互 `preload`
	- 豁免规则：
		- 仅包含枚举、常量映射的纯数据定义脚本，不受上述行数限制
13. **引用规范**：但涉及关卡配置、美术替换或需在编辑器预览的资源，优先使用 `@export` 的方式
	- **无挂载点禁用**：`@export` 仅对挂载在场景树中或已实例化的 `Resource` 生效；继承`RefCounted` 或 `Object` 等无挂载点的独立脚本严禁使用 `@export`
	- **分类优化与边界限制**：当`@export`内容过多的时候，使用`@export_group`进行分类管理；如果说调试某些内容有边界限制的时候则考虑使用`@export_range`、`@export_enum`、`@export_flags`、`@export_file`、`@export_dir`进行优化
	- **启动性能红线**：全局单例（`Autoload`）与全局类（`class_name`）严禁通过 `@export` 挂载重型资源，避免启动期强制递归拉入内存导致卡顿，重度场景须改用按需异步加载
	- **提示引用资源**：在生成完成之后，需要跟用户说明哪些需要引用什么资源
14. **总线引用**：
	- 全局变量中有 `信号总线.gd`
	- 当涉及的内容会跟全局有关时，从这里面寻找是否有可用的信号可以连接，例如`游戏开始`、`游戏失败`、`游戏暂停`等全局性的内容
	- 当某个内容涉及全局的，可以考虑向用户提出是否加入全局信号
15. **项目架构**：
	- 当游戏设计分函数/方法功能的时候，主逻辑内的数据层、表现层需要分出去，不能混在一起
	- 数据层内容仅处理数据并返回，表现层也仅处理表现内容
16. **复查流程**：生成后必须严格进行内部静态类型检查，并复查以上所有编程规范，不合格部分则按规范重写相应代码

## 规范示例（严格模仿此格式）
```gdscript
class_name 玩家控制器
extends CharacterBody2D


# 此脚本挂载于玩家角色根节点，作为核心控制器统筹输入处理与底层逻辑流转，并为跨场景交互提供类型基准


signal 玩家生命枯竭
signal 玩家受到伤害


enum 控制状态 { 自由行动, 锁定限制 }
enum 移动状态 { 站立, 奔跑, 腾空 }


const 常量_最大单次承受伤害: int = 9999
const 常量_基础移动速度: float = 300.0


## 用于在编辑器场景面板中快速调试角色的初始生存压力，避免频繁修改底层硬编码
@export var 初始生命: int = 100
## 用于策划在关卡设计时灵活配置角色的基础跳跃高度，以适配不同地形的平台跳跃需求
@export var 跳跃力度: float = 450.0


var 当前生命: int = 100
var 当前位置坐标: Vector2 = Vector2.ZERO


var _是否激活: bool = true
var _是否可以跳跃: bool = false


@onready var 玩家模型: 玩家场景 = %玩家场景
@onready var 动画播放器: AnimationPlayer = %动画播放器
@onready var 开始按钮: Button = %开始按钮


# 完成节点引用校验，重置基础战斗数据并建立底层事件信号监听
func _ready() -> void:
	_重置状态()
	玩家模型.生命变化.connect(_当玩家生命变化)
	开始按钮.pressed.connect(_当开始按钮按下)

# 实时更新角色坐标缓存，并持续检测重力或外界环境对角色的物理影响
func _physics_process(delta: float) -> void:
	当前位置坐标 = global_position
	_执行移动逻辑(delta)


# 对外提供统一的受击接口，供怪物或陷阱调用，以此触发扣血与硬直逻辑
func 承受外部伤害(伤害数值: int) -> void:
	var 实际伤害: int = min(伤害数值, 常量_最大单次承受伤害)
	当前生命 -= 实际伤害
	玩家受到伤害.emit()

# 对外提供生命值恢复接口，供拾取血包或治疗技能调用，并确保不超过初始生命上限
func 恢复生命值(恢复数值: int) -> void:
	当前生命 += 恢复数值
	if 当前生命 > 初始生命:
		当前生命 = 初始生命


# 接收并响应外部控制器（如开始游戏按钮）的触发指令，以激活当前角色的控制权限
func _当开始按钮按下() -> void:
	_是否激活 = true

# 将角色的生命值及状态标记强制恢复至初始配置，用于每次关卡重启或复活时的逻辑重置
func _重置状态() -> void:
	当前生命 = 初始生命
	_是否激活 = true

# 根据当前的物理速度向量与输入方向，计算并应用至物理引擎系统的最终移动结果
func _执行移动逻辑(过程时间: float) -> void:
	var 输入方向: float = Input.get_axis("左移", "右移")
	velocity.x += 输入方向 * 常量_基础移动速度 * 过程时间
	move_and_slide()

# 捕获并处理子节点抛出的生命值变化事件，进而判定是否需要触发死亡流程或播放特效
func _当玩家生命变化() -> void:
	if 当前生命 <= 0:
		玩家生命枯竭.emit()
```
