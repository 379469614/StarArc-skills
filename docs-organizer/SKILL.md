# 项目文档自动整理

## 核心原则
- **只写设计，不写实现**：文档回答"为什么这样设计""各系统怎么协作"，**不记录**脚本路径、节点路径、函数名、变量名、信号签名、`@export` 参数、uid 引用等代码结构信息——那些读代码就能得到，写进文档只会加速过期
   - ❌ 反面教材："修改 `Player.gd` 的 `take_damage` 函数，增加无敌帧参数 `invincible_time = 0.5`"
   - ✅ 正确写法："玩家受击后获得 0.5 秒无敌帧，期间不再受伤害"
- **用游戏设计师的语言描述**："玩家生命值归零时进入结算流程"，而不是 "HealthComponent 发射 died 信号"
- **单一事实来源**：每条设计只在一个地方定义，别处引用它；同一条规则在两篇文档里说法不同 = 文档已失效
- **文档和现状保持一致**：仅通过阅读文档，可以知道整个项目当前是什么状态的；所以文档的维护也以当前文档状态为准；如果增加、修改或者删除的内容是已有文档内的，则找到已有的文档进行修改
- **术语一致**：所有文档必须遵循 `00_总览与术语.md` 中定义的术语，禁止同义词漂移
- **最小必要内容**：只记录本次变更影响的设计事实；不为凑齐模板补写无关章节、空内容或推测内容
- **已确认优先**：只有已落地且已确认的当前行为才能写成规则；无法确认且会影响设计结论的问题，才允许标为待确认

## 执行流程（AI 必须遵守）
1. **影响面分析**：根据本次改动，列出可能受影响的文档清单（如：改了伤害公式 → 需更新 `04_数值框架.md` 和 `02_系统设计/战斗系统.md`）
2. **加载术语**：读取 `00_总览与术语.md`，作为本次维护的术语基准
3. **读取现状**：读取所有需要修改的文档当前内容
4. **选择章节**：先确定本次内容所需的最小章节；不适用的章节不创建、不保留空标题
5. **应用变更**：更新既有的单一事实来源；确无对应文档时才新建，确保使用游戏设计师语言，不写实现细节
6. **交叉校验**：检查本次修改是否与其他文档冲突，并删除或改正已过时的重复描述

## 文档路径
- 以`project.godot`所在路径为标准，找到的该文件所在目录即为项目根，文档目录固定为 `<项目根>再上一层的目录/1项目文档/`对应为`../1项目文档`
- 找不到 `project.godot` → 停止并询问用户项目根位置，不凭猜测写

## 目录结构
所有文档存放在 `../1项目文档/` 下，结构如下：

`../1项目文档/`
- `00_总览与术语.md` — 游戏核心概念、术语表、一句话描述、全局规则
- `01_核心循环.md` — 局内/局外核心循环
- `02_系统设计/` — 各系统（按实际项目增减），每个系统单独一个文档
- `03_玩法设计/` — 各玩法（按实际项目增减），每个玩法单独一个文档
- `04_数值框架.md` — 核心数值公式、经济循环、成长曲线等和游戏数值相关的内容
- `05_全局服务/` — 存档、设置、音频、本地化等基础设施，每个内容单独一个文档


## 文档结构
系统、玩法文档以“设计意图、核心流程、规则定义”为默认骨架；其余章节按实际需要选用，不适用时直接省略；一次小范围更新只修改受影响的段落，无需补全整篇模板

### 默认骨架
```
1. 设计意图
> 一句话说明这个系统解决什么问题、为玩家提供什么体验

2. 核心流程
[文字流程图 + 关键状态流转]

3. 规则定义
    3.1 [规则类别]
    - 规则一：...
    - 规则二：...

    3.2 [规则类别]
    - ...
```

### 按需章节
```
4. 与其他系统的交互（仅在存在跨系统设计影响时）
| 交互对象 | 交互结果/影响 | 触发条件 |
|---|---|---|
| 战斗系统 | 使用本系统确定的伤害规则 | 玩家攻击时 |
| 界面反馈 | 展示生命值变化 | 生命值变动时 |

5. 数值设计（仅在该文档是对应数值的单一事实来源时）
[公式 / 参数表 / 成长曲线]
```

### 待确认项（条件追加）
- 仅当存在无法从当前项目资料确认、且会阻塞设计结论或后续实现的问题时，才在文末追加“待确认项”
- 每项必须说明缺失事实和需要谁/如何确认；不存在真实问题时不得创建此章节，严禁为填充模板编造条目

## 文档类型边界
- `00_总览与术语.md`：仅维护项目定位、全局规则和术语，不套用系统模板
- `01_核心循环.md`：仅维护局内/局外循环及其衔接，不套用系统模板
- `04_数值框架.md`：作为跨系统核心公式、经济循环和成长曲线的单一事实来源
- `05_全局服务/`：记录服务面向玩家或系统提供的能力、规则与边界；仅在适用时使用流程或交互章节
