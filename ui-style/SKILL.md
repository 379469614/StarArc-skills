# 通用UI规范
>可以跨项目通用的规范

## 一、基本原则
1. 处理 Godot UI 时，优先保持项目现有结构和实现方式一致
2. UI结构应简单、清晰，避免无必要的复杂设计
3. 未明确要求时，不主动进行大规模重构

## 二、界面结构
1. 完整界面默认使用 `CanvasLayer` 作为根节点
2. 局部UI组件根据实际需求使用 `Control` 或其他合适节点
3. UI布局优先使用 `Container`、`Anchor`、`Container Sizing` 等Godot原生布局方式，避免大量依赖固定坐标硬编码布局

## 三、UI组件拆分
1. 已经重复使用2次及以上的UI结构，应考虑拆分为独立组件
2. 需求明确说明后续需要复用的UI，即使当前只使用1次，也可以提前拆分
3. 列表项、卡牌、商品格、设置项等明显批量实例化结构，应独立为组件
4. 单次使用但结构复杂、职责独立的UI，可以根据实际情况拆分
5. 当前只使用1次、结构简单、没有明确复用需求的UI，默认不拆分
6. 不允许仅因为“未来可能复用”而提前抽象组件

## 四、AI执行原则
1. 修改UI前先检查当前项目已有UI结构和组件
2. 优先复用已有组件和实现方式
3. 用户明确指定结构时，以用户要求为最高优先级
4. 无法确定是否需要拆分组件时，默认采用更简单的实现
5. AI可以指出潜在复用可能，但不能仅凭预测主动进行过度抽象
6. 新增UI时尽量保持与现有界面的节点结构、命名和布局方式一致

## 五、UI脚本规范
- UI 脚本仅处理界面的显示、动画和用户交互（如按钮点击）
- 严禁在 UI 脚本中直接处理核心业务逻辑或修改游戏存档
- UI向业务层发送操作意图时优先使用Signal或已有事件机制，不直接承担业务状态修改职责

## 六、主题控制
- 默认使用全局主题控制通用UI样式
- 节点默认不使用 Theme Overrides，优先通过主题资源统一管理
- 仅针对单个节点且无复用价值的特殊样式，允许少量使用 Theme Overrides
- 可复用的特殊样式应建立独立主题资源


# 项目UI规范
>每个项目自己的一份规范，在具体项目执行的时候仍然要读取当前项目的规范文件并遵守

## 一、文档整理
- 每个项目都有自己独立的一份UI规范
- 文档路径根据`folder-structure`技能的`全目录`路径放在`全目录/5UI规范/`
- 在该文件夹下文档分类如下
  - 00_UI总则.md
    - 新建UI、调整整体UI方向、适配平台或修改项目UI基本原则时需要读取或维护这份文档
  - 01_视觉规范.md
    - 新增或修改节点Theme，尤其是全局Theme及可复用Theme资源时，需要读取这份文档；涉及项目统一视觉规则变化时需要同步维护
  - 02_组件规范.md
    - 新增、修改或复用按钮、标签、面板、弹窗、列表项等UI组件时需要读取或维护这份文档
  - 03_界面结构规范.md
    - 新增界面、调整界面节点结构、布局方式或界面组成时需要读取或维护这份文档
  - 04_交互规范.md
    - 新增或修改点击、返回、关闭、确认、禁用、动画反馈等UI交互行为时需要读取或维护这份文档
  - 05_CanvasLayer层级管理.md
    - 新增界面（CanvasLayer）或修改CanvasLayer层级的时候需要维护这份文档

## 二、新建规范
- 当该目录缺乏这些内容的时候，则说明当前项目是新项目，需要重新建立一套UI规范
- 读取当前技能目录的模板文件作为基础规范，并和用户讨论一些项目定调的内容，以此完善整个项目的基调
