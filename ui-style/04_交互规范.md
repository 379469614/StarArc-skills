# 04_交互规范

> 记录项目 UI 交互的强制约束，用于避免误触、操作困难、重复触发等问题

## 一、点击区域
1. 移动端所有可交互控件的有效点击区域不得小于 `64 × 64 px`
2. 以上尺寸以 `1280 × 720` 或 `720 × 1280` 设计分辨率为基准
3. 图标视觉尺寸允许小于 `64 × 64 px`，但实际可点击区域仍不得低于该尺寸
4. 重要操作按钮建议高度不低于 `80 px`
5. 相邻独立点击区域之间建议至少保留 `12 px` 间隔
6. 不允许依赖极窄边缘、细线或小文字作为唯一点击区域

## 二、触摸操作
1. 常规按钮以单次点击作为默认操作，不要求用户长按
2. 长按操作仅用于明确设计为长按的功能，不得替代常规点击
3. 不允许将双击作为核心功能的唯一触发方式
4. 拖拽操作必须提供足够大的起始触摸区域
5. 拖拽开始后，不因手指轻微偏离原控件立即取消操作
6. 不要求用户进行高精度像素级拖拽或点击

## 三、误触限制
1. 危险操作不得与高频操作按钮紧贴排列
2. 删除、清空、退出进度等不可逆操作必须提供二次确认或撤销机制
3. 连续点击同一按钮不得重复触发同一业务操作
4. 页面切换、购买、提交等操作触发后，在结果返回前应暂时禁止重复触发
5. 屏幕边缘区域不得放置需要高频精准操作的小型按钮

## 四、操作反馈
1. 所有可点击控件必须具有明确的按下反馈
2. 点击后产生明显状态变化的操作，应在当前交互周期内提供视觉反馈
3. 耗时操作必须显示进行中状态，不允许点击后长时间无反馈
4. 禁用状态必须与正常可点击状态存在明显视觉区别
5. 不允许仅通过颜色变化表达关键状态，应同时通过图标、文字或形态进行区分

## 五、按钮状态
1. Button 类交互控件至少考虑 `正常 / 按下 / 禁用` 三种状态
2. PC 或 Web 平台需要鼠标操作时，再补充 `悬停` 状态
3. 禁用按钮不得响应点击事件
4. 当前条件无法执行的操作，优先显示禁用状态，而不是点击后再提示无法执行
5. 同一界面中的相同类型按钮应保持一致的交互状态规则

## 六、弹窗交互
1. 模态弹窗打开后，不允许操作其下层界面
2. 弹窗的主要操作与关闭操作不得使用相同视觉权重
3. 关闭按钮必须具备不小于 `64 × 64 px` 的有效点击区域
4. 点击弹窗外区域是否关闭弹窗必须由该弹窗明确规定，不允许默认随意实现
5. 涉及确认选择的弹窗不得因误触背景区域直接关闭

## 七、页面切换
1. 页面切换期间不得重复触发相同跳转
2. 返回操作必须回到用户可预期的上一级界面
3. 页面切换后不得保留上一个界面的不可见交互区域
4. 新界面出现前，不允许用户提前点击尚未完成初始化的控件

## 八、输入优先级
1. 同一触摸输入只能由一个主要交互对象消费
2. 上层弹窗存在时，下层 UI 不得同时响应输入
3. UI 与游戏场景发生触摸区域重叠时，优先由 UI 消费输入
4. 拖拽开始后，应保持当前拖拽对象的输入所有权，直到拖拽结束或主动取消
