# 03_界面结构规范

> 记录项目 UI 界面在节点结构、层级组织、布局方式与组件拆分上的强制约束

## 一、根节点结构
1. 完整独立界面默认使用 `CanvasLayer` 作为根节点
2. 局部 UI 组件不得使用 `CanvasLayer`，应使用 `Control` 或其他 UI 节点
3. 同一完整界面不得无必要嵌套多个 `CanvasLayer`
4. 不允许使用 `Node2D` 作为纯 UI 界面的主要布局根节点
5. 界面根节点只负责界面级组织，不直接堆放大量业务子节点

## 二、层级数量
1. UI 节点层级应保持扁平
2. 无明确布局、遮罩、裁剪或功能需求时，不得增加中间容器节点
3. 单纯用于分类且不承担任何功能的空节点不得连续嵌套
4. 同一 UI 结构连续嵌套超过 `5` 层时，应检查是否存在可合并节点
5. 不允许通过大量无功能 `Control` 节点人为调整层级

## 三、布局方式
1. 常规 UI 布局优先使用 `Container`、Anchor 与 Offset
2. 不允许大量依赖固定坐标实现可适配界面
3. 不允许同时使用互相冲突的布局方式控制同一节点位置
4. 需要随父节点尺寸变化的控件，不得只设置固定像素位置
5. 重复排列的同类元素不得手动逐个定位，应使用对应 `Container`
6. UI 节点不得依赖运行时脚本持续修正基础布局位置

## 四、锚点与尺寸
1. 全屏界面主体必须明确设置为随视口尺寸变化
2. 需要贴边的 UI 必须使用 Anchor 表达贴边关系
3. 固定尺寸控件不得错误设置为全尺寸拉伸
4. 背景类节点应覆盖其所属界面的完整可视区域
5. 不允许通过超大 Offset 数值替代正确的 Anchor 设置
6. 控件最小尺寸应由实际内容和交互需求决定，不得依赖偶然撑开

## 五、组件拆分
1. 同一 UI 结构重复使用 `2` 次及以上时，应优先拆分为独立组件
2. 具有独立状态、独立交互或独立复用价值的模块应拆分为独立组件
3. 仅包含少量静态节点且只使用一次的结构不得过度拆分
4. 独立组件内部不得直接依赖具体页面的兄弟节点
5. 组件不得通过硬编码路径访问外部界面节点
6. 页面级逻辑与通用组件逻辑不得混杂在同一组件内

## 六、页面职责
1. 一个完整界面只负责当前页面范围内的 UI
2. 不允许在一个界面场景中同时长期保留多个互斥主页面
3. 大型页面切换应通过独立场景或独立界面节点管理
4. 不属于当前页面的隐藏 UI 不得长期驻留，仅为后续页面提前保留
5. 页面根节点不得承担全局 UI 管理职责
6. 全局 UI 功能应由专门的全局层或管理节点负责

## 七、弹窗结构
1. 独立弹窗必须作为完整 UI 单元管理
2. 弹窗背景遮罩、主体内容与交互按钮应处于同一弹窗结构内
3. 弹窗不得直接散落挂载在页面多个不同层级
4. 同一弹窗内部不得再无必要嵌套独立 `CanvasLayer`
5. 弹窗关闭后，其节点应隐藏或释放，不得保留不可见交互区域
6. 模态弹窗必须明确位于普通页面 UI 之上

## 八、HUD 与页面 UI
1. 游戏内持续显示的 HUD 与菜单、弹窗等页面 UI 应分层管理
2. HUD 不得与临时弹窗混杂在同一普通容器内
3. HUD 中长期存在的状态信息应保持固定结构
4. 临时提示、飘字、Toast 等短生命周期 UI 不得挂在普通 HUD 内容节点下
5. 游戏世界内跟随对象移动的 UI 不得与屏幕固定 UI 使用同一布局体系

## 九、节点命名与职责
1. 一个节点应只承担一个明确的主要职责
2. 不允许使用大量 `Control`、`Panel`、`Node` 等无语义名称
3. 容器节点名称应能体现其布局或内容职责
4. 视觉节点、交互节点与数据承载节点不得通过名称混淆职责
5. 不允许为了临时调试留下长期无用途节点
6. 已废弃或未使用的 UI 节点必须删除，不得长期隐藏保留

## 十、禁止结构
1. 禁止完整界面使用大量绝对坐标硬编码布局
2. 禁止无功能意义的多层空节点嵌套
3. 禁止局部组件随意创建 `CanvasLayer`
4. 禁止跨组件硬编码节点路径访问
5. 禁止同一界面同时存在多套互相重叠的主布局
6. 禁止通过隐藏大量旧节点的方式保留废弃 UI
7. 禁止单一场景无限堆叠所有页面、弹窗、HUD 与临时 UI
