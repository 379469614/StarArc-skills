# 网页游戏掉帧原因与修复指南

## 1. 文档用途

1. 本文记录 Godot Web 导出包的同步查询问题。
2. 目标读者为开发者和后续接手的 Agent。
3. 其他项目接入 CrazyGames 时可参考本文。
4. 适配前应先检查调用栈和连续帧率。
5. 本文不代表所有网页掉帧都由此问题引起。
6. 本次调查日期为 2026-10-26。

## 2. 问题摘要

1. 本地独立网页运行接近 60 FPS。
2. CrazyGames 内运行约为 32 FPS。
3. 平台没有将该游戏固定限制为 30 FPS。
4. 主要瓶颈来自逐帧的图形状态同步查询。
5. 调用方是导出包自带的 Emscripten 运行库。
6. 调用入口为 `GL.blitOffscreenFramebuffer`。
7. 耗时查询为 `gl.getParameter(gl.SCISSOR_TEST)`。
8. `SCISSOR_TEST` 的枚举值为 `0x0C11`，即 `3089`。
9. 它表示裁剪测试是否开启。
10. 改用 `gl.isEnabled(gl.SCISSOR_TEST)` 后恢复约 60 FPS。

## 3. 根因与证据边界

### 3.1 提交画面的调用链

1. Godot Web 创建上下文时启用 `explicitSwapControl`。
2. 当前导出运行库使用离屏帧缓冲。
3. 每帧提交时调用 `emscripten_webgl_commit_frame`。
4. 它调用 `GL.blitOffscreenFramebuffer`。
5. 运行库先查询裁剪状态，再复制最终画面。
6. 复制结束后，运行库恢复原裁剪状态。
7. 因此该状态查询通常每帧执行一次。

### 3.2 为什么这个查询很慢

1. 当前浏览器将该查询转为 `GetBooleanv`。
2. 查询未命中客户端缓存时，需要等待 GPU 进程。
3. 等待会阻塞调用它的线程。
4. 这种等待会打断 CPU/GPU 的流水线并行。
5. `isEnabled` 对相同开关可走客户端状态路径。
6. 本次实机测量确认了两条路径的耗时差异。
7. 这不意味着所有参数查询都能改用 `isEnabled`。
8. 本修复只处理 `SCISSOR_TEST`。

### 3.3 已确认的环境差异

1. 手机为 Redmi K40，Android 13。
2. 浏览器为 Edge，内核报告 Chrome 156。
3. GPU 为 Adreno 650，使用 ANGLE OpenGL ES。
4. 平台内游戏运行于跨域 iframe。
5. 本地独立页的功耗偏好为 `default`。
6. 跨域嵌入页的实际偏好为 `low-power`。
7. 两边的引擎都请求了 `default`。
8. Chromium 源码会重写跨域画布的功耗偏好。
9. 该偏好不等于已证明 GPU 被降频。
10. 本次未单独量化各项嵌入策略的贡献。
11. 同一图形查询在不同环境中的等待并不相同。
12. 本地跨域页也复现了性能下降。
13. 因此 CrazyGames 外层页面并非必要触发条件。

## 4. 实机测量结果

| 条件 | 连续采样 | 平均绘制提交 FPS | 每帧回调耗时中位数 | 画布像素 |
| --- | ---: | ---: | ---: | --- |
| CrazyGames，原始查询 | 20 秒 | 32.45 | 28.0 ms | 1080×2233 |
| CrazyGames，临时跟踪状态缓存 | 12 秒 | 60.51 | 7.7 ms | 1080×2233 |
| CrazyGames，恢复原始查询 | 8 秒 | 33.33 | 27.1 ms | 1080×2233 |
| CrazyGames，原生 isEnabled | 12 秒 | 60.41 | 7.4 ms | 1080×2233 |
| 本地独立页，矿区 | 12 秒 | 60.56 | 13.21 ms | 1078×2032 |
| 本地跨域页，稳定阶段原始查询 | 12 秒 | 39.65 | 22.0 ms | 1080×2233 |
| 同一本地跨域场景，原生 isEnabled | 12 秒 | 60.57 | 11.4 ms | 1080×2233 |

1. 跨域稳定阶段的绘制次数均为每帧 63 次。
2. 对照期间保留了相同分辨率。
3. 原始查询记录了 236 次调用。
4. 累计耗时 1846.3 ms，平均约 7.82 ms。
5. 原生查询记录了 726 次调用。
6. 累计耗时仅为 4.7 ms。
7. 同一实例切换查询方式最能支持因果判断。
8. 不同实例的游戏状态并不完全一致。
9. 不能将不同实例的所有差值都归于嵌入。
10. 降低平台内画布分辨率没有明显改善帧率。
11. 本次首要瓶颈不在像素数量。

### 4.1 测量口径

1. 记录实际发生 WebGL 绘制的帧回调时间。
2. 单独的浏览器动画回调不能冒充游戏帧率。
3. 本次帧率没有从截图读取。
4. 绘制提交频率不等于屏幕最终呈现频率。
5. 读数略超 60 可能来自计时和调度误差。
6. 每帧回调耗时包含计算及同步等待。
7. 它不能直接当作纯 CPU 计算时间。
8. 采样工具本身也有开销。

## 5. 可复用修复方案

### 5.1 安装代码

1. 将以下脚本放在引擎脚本之前。
2. 脚本同时兼容 WebGL 1 和 WebGL 2。
3. 脚本仅替换裁剪开关的查询路径。
4. 其他参数仍交给原始查询函数。
5. 标记可以避免同一页面重复安装。
6. 返回值来自浏览器实时状态。
7. 不需要自行维护 enable/disable 状态缓存。

```html
<script>
// 避免每帧查询裁剪状态时同步等待 GPU 进程。
(function () {
	const marker = Symbol.for('godot.webgl.scissor-query-fix');
	for (const Context of [window.WebGL2RenderingContext, window.WebGLRenderingContext]) {
		if (!Context || Context.prototype.getParameter[marker]) {
			continue;
		}
		const originalGetParameter = Context.prototype.getParameter;
		const getParameter = function (parameter) {
			return parameter === 0x0C11
				? this.isEnabled(parameter)
				: originalGetParameter.call(this, parameter);
		};
		Object.defineProperty(getParameter, marker, { value: true });
		Context.prototype.getParameter = getParameter;
	}
})();
		</script>
```

### 5.2 Agent 集成步骤

1. 确认项目实际使用的 HTML 来源。
2. 检查导出脚本是否覆盖引擎生成的 HTML。
3. 优先修改可重复导出的源模板。
4. 也可通过自定义导出模板安装处理。
5. 使用 Head Include 时，应确认它未被后续覆盖。
6. 将处理放在 `index.js` 或 `index.js.br` 之前。
7. 不要仅修改一次性的生成文件。
8. 保留项目既有的资源路径和压缩适配。
9. 不要把 GL_SCISSOR_TEST 枚举值改成其他状态。
10. 不要为所有 getParameter 参数返回固定值。
11. 不要用降低分辨率代替已定位的查询修复。
12. 后续升级引擎时，应复查上游提交路径。
13. 上游解决该问题后，应评估移除兼容处理。

### 5.3 本项目的集成位置

1. HTML 源模板为本目录的 `index.html`。
2. 打包入口为本目录的 `导出设置.sh`。
3. `run_pack` 保留源模板，并写入本次导出的引擎配置。
4. 因此后续打包会自动携带本修复。
5. 本修复不要求修改玩法 GDScript。
6. 本修复不改变画质设置和游戏规则。

### 5.4 构建版本注意事项

1. 本项目只对原始 PCK、JS、WASM 计算版本哈希。
2. 当前算法没有计入 HTML 源模板。
3. 因此单独修改 HTML 可能不会增加 Build 编号。
4. 不应通过手工改显示文字来伪造新版本。
5. 其他项目应检查自己的版本计算范围。
6. 若需用版本号追踪网页适配，应纳入模板变化。
7. 调整版本算法属于独立维护事项。

## 6. 后续项目的验证与回滚

1. 先记录原始状态下的连续帧率。
2. 使用同一设备、浏览器及游戏场景。
3. 保持相同画布像素和前后台状态。
4. 记录温度、省电模式和画面提交耗时。
5. 临时启用修复，保持其余条件不变。
6. 再恢复原查询，确认掉帧是否重新出现。
7. 若修复前后没有差异，应继续定位其他瓶颈。
8. 不要将本文结论套用到所有平台或设备。
9. 正式集成后，应在目标平台重新验证。
10. 回滚时删除第 5.1 节脚本，再重新导出。
11. 动态视觉与交互正确性仍需实机检查。
12. 本次按用户要求不继续监测打包后的游戏。

## 7. 上游参考

1. [Godot Web 上下文创建](https://github.com/godotengine/godot/blob/master/platform/web/display_server_web.cpp)：`explicitSwapControl`。
2. [Emscripten WebGL 运行库](https://github.com/emscripten-core/emscripten/blob/main/src/lib/libwebgl.js)：`blitOffscreenFramebuffer`。
3. [Chromium WebGL 实现](https://github.com/chromium/chromium/blob/main/third_party/blink/renderer/modules/webgl/webgl_rendering_context_base.cc)：两种查询入口。
4. [Chromium GL 客户端实现](https://github.com/chromium/chromium/blob/main/gpu/command_buffer/client/gles2_implementation.cc)：客户端状态读取。
5. [Chromium GL 查询与等待](https://github.com/chromium/chromium/blob/main/gpu/command_buffer/client/gles2_implementation_impl_autogen.h)：`GetBooleanv` 和 `WaitForCmd`。
6. [Chromium 画布创建](https://github.com/chromium/chromium/blob/main/third_party/blink/renderer/core/html/canvas/html_canvas_element.cc)：跨域功耗偏好。
7. [MDN WebGL 性能建议](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices#avoid_blocking_api_calls_in_production)：避免阻塞式查询。
8. 上述源码链接指向持续变化的上游分支。
9. 当前设备的调用栈与对照数据独立支持本结论。

## 正式矿区分块后的导出约束

1. 正式发布使用同版本官方单线程Web模板。
2. 自定义裁剪模板曾出现瓦片绘制遗漏。
3. 每次导出保留当次生成的JS与WASM。
4. 压缩当次JS、WASM与PCK，不复制旧引擎压缩包。
5. 宿主页使用当次生成的文件尺寸与引擎配置。
6. 本地启动通过不等于手机或CrazyGames平台验收。
