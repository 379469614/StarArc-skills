# 项目文档自动整理

## 核心原则
1. **只写设计，不写实现**：文档回答"为什么这样设计""各系统怎么协作"，**不记录**脚本路径、节点路径、函数名、变量名、信号签名、`@export` 参数、uid 引用等代码结构信息——那些读代码就能得到，写进文档只会加速过期
2. **用游戏设计师的语言描述**："玩家生命值归零时进入结算流程"，而不是 "HealthComponent 发射 died 信号"
3. **单一事实来源**：每条设计只在一个地方定义，别处引用它；同一条规则在两篇文档里说法不同 = 文档已失效
4. **文档和现状保持一致**：仅通过阅读文档，可以知道整个项目当前是什么状态的；所以文档的维护也以当前文档状态为准



当AI完成操作之后，自动将当前修改的内容重新整合维护到“../1项目文档/”里，使该文件夹的文档可以对当前整个项目的状态、设计保持文档内容的准确性和完整性
如果在整合的过程中如果发现一些设计与原先已有的设计有较大的冲突，需要向用户提出
维护的文件结构按系统和功能进行划分
