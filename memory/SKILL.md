# 记忆维护

## 唯一目录和远端

所有记忆维护均基于 `~/.codex/memories`。该目录也是唯一的记忆 Git 仓库。不维护独立脱敏副本或第二个记忆仓库。

通过操作系统提供的当前用户主目录定位实际路径。Unix 类系统通常为 `$HOME/.codex/memories`，Windows 通常为当前用户配置目录下的 `.codex/memories`。使用运行环境的路径接口解析主目录和分隔符。不要把 `~` 当成普通目录名，也不要依赖 shell 必然展开它。

不要硬编码用户名、盘符或 Documents、文档等名称。Codex 聊天工作目录的迁移不改变记忆目录。不要从工作目录推断记忆目录。

- GitHub 仓库：`https://github.com/379469614/Codex-personal-memery`。
- SSH 远端：`git@github.com:379469614/Codex-personal-memery.git`。
- HTTPS 远端：`https://github.com/379469614/Codex-personal-memery.git`。
- 默认远端名：`origin`。默认分支：`main`。

先核对 Git 根目录确实等于记忆目录。若它属于父目录的仓库，停止并报告。缺少仓库时，按下述首次同步流程处理。

## 授权和边界

Plan 阶段仅执行只读检查。获得本轮 `act` 后执行维护及收尾。说明本轮范围时，包含敏感信息清理、提交和推送。已有授权覆盖这些步骤时，不重复询问。

更高优先级的记忆写入限制仍然有效。只能使用补充说明机制时，不直接改写受限文件。无法清除现存敏感信息时，停止提交和推送并报告限制。不得改用独立脱敏仓库绕过限制。

本技能在 Codex 维护记忆后自动收尾。它不是后台文件监控程序。其他程序的修改不会自动触发本技能。

本技能不授权删除旧备份仓库、重写历史或强制推送。这些操作须另行明确范围。

## 维护前同步

1. 检查目录、Git 根目录、分支、工作区和远端。保留已有修改，不自动清理、覆盖、stash 或提交不相关内容。
2. 缺少 `origin` 时，在授权范围内添加指定远端。SSH 与 HTTPS 均须指向上述仓库。地址不符时暂停，不静默替换。
3. 先读取远端引用，再 fetch。远端有历史时，先在获取的对象中检查敏感信息，再考虑检出或合并。不得未经检查就把远端敏感内容拉入记忆工作区。
4. 本地目录缺失且远端有历史时，在目标目录使用不检出工作区的 clone。检查远端对象通过后，再检出 `main`。不创建第二个长期记忆仓库。
5. 本地目录已有内容但尚无 Git 仓库时，禁止直接 clone 覆盖。先检查内容、远端及重叠文件，再确定不覆盖本地文件的接入方案。
6. 远端没有 `main` 时，无需 pull。检查其他分支，确认没有遗漏需保留的历史，再准备首次推送。
7. 本地与远端相同时继续。本地仅领先时，检查未推送提交。本地仅落后且工作区干净时，在远端内容检查通过后，执行快进拉取。
8. 历史分叉、历史无关或工作区阻止拉取时，暂停并报告。禁止自动硬重置、强制推送或合并无关历史。

pull 只同步 Git 已记录的内容，不能证明记忆完整。还需核对文件清单和内容。本地缺少远端文件时，应先同步，而不是直接推送覆盖。远端没有本地文件时，也不能直接判定本地文件应删除。

本地空、远端非空时，先检查并恢复远端内容。远端空、本地非空时，先审查本地文件与历史，再首次推送。两端都空时，只在唯一目录中初始化。

现存本地历史与远端历史无关时，不能直接 pull。报告差异并另定接入方案。不得以合并无关历史为由重新引入旧敏感信息。

## 写入前排除敏感信息

记忆只保存任务结论、操作方法、必要背景和注意事项。不要保存密码、密钥、令牌及连接凭据。需要连接信息时，从当前获准的配置来源读取，不复制进记忆。

在任何内容落盘前，检查拟写入文本。直接省略不必要的敏感细节。只有省略会影响理解时，才使用明确占位符，如 `[REDACTED_SECRET]`。不要为了记录脱敏过程而保存原值或替换映射。

检查新增和修改内容，也检查本轮涉及的现存记忆。发现既有敏感内容时，在权限及授权允许的范围内清除。无法清除时停止同步并报告。禁止先把原文写入记忆，再依赖上传前脱敏。

检查范围包括：

- 私钥、访问令牌、API 密钥、明文密码和认证头。
- 带凭据的 URL、连接字符串、Cookie 和恢复码。
- 私有服务器公网地址、SSH 用户名和远程服务路径。
- 私人联系方式、身份信息及非公开业务信息。
- 正文、代码示例、摘要、补充说明和辅助差异文件。
- Git 提交身份、提交说明及待上传历史中的隐私。

字段名称不等于真实凭据。公开项目地址、公开文档和普通本机路径不自动认定为秘密。结合上下文判断；不确定时暂停相关写入和上传。

工具输出、报告和提交说明不得复述敏感原文。只报告类别、文件、位置和数量。排除凭据文件、临时文件、缓存、日志及不明二进制文件。不得通过符号链接读取或上传范围外内容。

## 提交前检查

仅暂存本轮获准维护的记忆文件。逐项检查新增、修改和删除。不要使用无差别暂存来纳入并发产生的文件。删除须有明确原因，不因本地缺失就删除远端记忆。

检查实际暂存版本，不以工作区检查代替。内容包含敏感信息时，先清除工作区及暂存版本，再重新检查。确认扫描对象与提交对象一致。

使用获准提交身份。没有明确身份时，可对本次提交使用占位身份 `Memory Maintenance <memory@localhost>`。不要修改全局 Git 身份。

有获准且检查通过的变化时自动提交。没有变化时不创建空提交。存在已检查的未推送提交时，继续推送流程。

## 推送前检查历史

首次推送时检查全部将上传的可达历史。后续推送时检查全部待推送提交及对应文件版本。不能只扫描当前文件或最新一次提交。

当前文件已清理，不代表旧历史已清理。旧历史仍有敏感信息时，禁止推送。报告是否涉及本地未发布历史或远端已发布历史，再另定清理方案。未经明确授权，不重写历史或强制推送。

发现已上传的有效密钥或令牌时，提醒用户撤销或轮换。删除文件或改写历史不能让凭据自动失效。

推送前再次获取远端状态，判断提交关系。远端有新变化时，先按维护前同步流程处理。若引入新内容，重新执行敏感信息检查。

使用一次确定的目标提交完成审查和推送。发现并发改动时重新确认范围。禁止让未审查的提交混入本次推送。

## 推送与验证

正常推送已审查的提交到 `origin/main`，并建立上游关联。禁止推送无关分支、标签或全部引用。禁止强制推送。

推送后重新读取远端 `main` 的提交值，核对它与已审查的本地目标提交一致。若本地 `HEAD` 已变化，单独说明未同步部分，不误报全部同步成功。

检查工作区、暂存区及未推送提交。只有远端核对通过，才报告推送成功。远端又被更新时，重新判断状态，不覆盖并发修改。

网络故障时保留本地内容和提交。可对短暂网络故障重试一次，仍失败则报告。冲突、认证失败和主机密钥异常不得盲目重试。

保留 SSH 主机密钥校验。未知主机密钥须通过可信渠道核验。不得降低连接安全性以完成推送。

## 完成报告

简要报告维护范围、敏感信息检查范围、清理结果、提交值、推送结果和远端一致性。明确未完成项及权限限制。

不输出敏感原文。不把规则扫描描述为绝对安全保证。未完成清理时，明确说明没有推送。
