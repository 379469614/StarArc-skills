# 记忆维护

## 目录与远端

- 记忆目录：`~/.codex/memories`，使用当前系统的用户主目录和路径接口解析
- 远端：`git@github.com:379469614/Codex-personal-memery.git`
- HTTPS 等价地址：`https://github.com/379469614/Codex-personal-memery.git`
- 远端名：`origin`，分支：`main`

核对 Git 根目录等于记忆目录，缺少远端时配置上述地址；地址指向其他仓库时停止并报告

## 维护前同步

先检查工作区，再 fetch 并比较本地与远端，保留未提交内容，不覆盖或自动丢弃

- 本地目录为空、远端有内容：先不检出地 clone 到记忆目录，审查内容后再检出
- 本地已有文件但没有 Git 仓库：检查文件重叠情况，再确定接入方案，避免覆盖
- 远端为空：审查本地文件与历史后准备首次推送，无需 pull
- 本地落后、工作区干净：审查远端内容后快进拉取
- 本地领先：检查未推送提交后继续维护
- 历史分叉、历史无关或工作区阻止拉取：停止并报告

检查远端其他分支，避免把缺少 `main` 误判为仓库为空；核对文件清单，不能仅凭提交关系判断记忆完整；拉取前检查新内容，防止重新写入敏感信息

## 敏感信息处理

记忆保留任务结论、操作方法和必要背景，连接信息按需从配置来源读取

写入前检查拟保存内容，剔除以下信息：

- 密码、私钥、令牌、API 密钥和恢复码
- 认证头、Cookie、带凭据的 URL 和连接字符串
- 私有服务器地址、SSH 用户名和远程服务路径
- 私人联系方式、身份信息和非公开业务信息

优先省略敏感细节；只有影响理解时才使用占位符；结合上下文区分字段名、公开资料和真实敏感值

检查正文、代码示例、摘要、补充说明和辅助文件；发现既有敏感信息时，在允许范围内清除；无法清除或无法判断时停止提交和推送；报告只列类别和位置，不输出原值或替换映射

## 自动提交与推送

1. 检查本轮新增、修改和删除，只暂存获准且相关的记忆文件；排除凭据文件、缓存、日志和范围外符号链接
2. 扫描实际暂存内容，剔除敏感信息后重新检查；确认提交内容与审查内容一致
3. 有变化时自动提交，无变化时不创建空提交；提交身份和说明也须检查隐私；必要时对本次提交使用 `Memory Maintenance <memory@localhost>`
4. 推送前检查待上传历史中的文件版本；首次推送检查全部将上传的历史，后续检查未推送提交；旧历史仍含敏感信息时停止，另定历史清理方案
5. 再次获取远端状态；远端变化时重新同步和审查；不得通过强制推送、硬重置或合并无关历史解决差异
6. 将审查通过的目标提交推送到 `origin/main`；已有未推送提交时，即使本轮无文件变化，也需检查后推送
7. 重新读取远端提交值，核对其与目标提交一致；检查工作区和剩余未推送内容，再报告同步结果

发现并发修改时，重新确认检查范围；推送失败时保留本地提交并报告，不把本地提交成功视为远端保存成功

发现已上传的有效凭据时，提醒撤销或轮换；清除历史不能使凭据失效
