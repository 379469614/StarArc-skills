description: 当用户说“提交”或“合并任务“时或准备进行git操作时，调用此技能
---

# 提交规范
- 提交仅提交当前会话对应任务相关修改的内容
- 不可以提交跟本任务无关的内容
- 如果是同一个文件内有多段来自不同会话修改的，则需要拆分出跟当前会话相关的部分进行提交
- 提交信息需要从功能向说明清楚当前的修改内容，而不是改了什么文件之类的无用信息

# 工作树提交规范
1. 当用户说“合并任务”的时候是指将当前会话工作树修改的内容提交并创建分支合并到main，此提交也准循提交规范
2. 提交前检查当前 Worktree、Git 状态及变更范围
3. detached HEAD 下需要长期保存或合并成果时，创建任务分支
4. 允许自主完成当前任务的普通 Git 提交
5. 合并 main 前必须检查目标分支状态
6. main 存在未提交修改或其他合并任务时，分情况处理；如果只是文档冲突，则基本都是新增的话，则都保留并合并；代码功能如果只是额外新增也可以直接都保留并合并；其他情况则暂停并报告
7. 遇到无法安全解决的合并冲突时，停止并报告
8. 禁止擅自丢弃、覆盖其他 Worktree 或 main 的修改
9. 禁止未经授权执行破坏性 Git 操作
10. 合并完成后执行必要的自动化测试，并报告结果
11. 默认保留任务 Worktree 和分支，清理需用户确认
